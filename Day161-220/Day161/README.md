## 평가 목표 (정답·구현 세부 사항은 비공개)

- 소스를 제공하지 않은 **stripped x86-64 ELF**에서 사용 가능한 정보와 신뢰할 수 없는 정보의 출처를 구분한다.
- 입력 전달부터 메모리 변화·제어 흐름까지 독립 복원하고, **leak → 주소 해석 → 통제된 로컬 기능 목표**를 실제 실행으로 입증한다.
- 단순 정상 입력 수락 출력이나 프로세스 종료를 성공이라고 간주하지 않는다. 함수·주소·보호기법·조건을 디스어셈블리와 런타임 증거로 교차 확인한다.
- 단일 성공으로 끝내지 않는다. **20회 별도 프로세스 실행** 결과를 그대로 남겨 성공률과 실패 종류를 계산한다. 의도적으로 실패한 시도도 버리지 않는다.
- 범위: 사용자 본인의 로컬 바이너리에서 출력되는 성공 표식 검증. 네트워크·외부 시스템 접근이나 실제 쉘 확보는 요구하지 않는다.

## 환경 준비

Ubuntu/WSL x86-64, GLIBC 2.34 이상, GCC는 *필요 없음*. GDB/pwndbg·objdump·readelf·pwntools/ROPgadget 등 사용 가능. ELF는 Git의 ASCII armored 파일을 검증하며 복원한다.

```bash
cd /mnt/d/security-roadmap
git status --short
git pull --ff-only
cd Day161-220/Day161
bash unpack.sh
bash record.sh
```

`record.sh`로 열린 **새 bash 셸**에서 모든 분석을 수행한다. 세션 종료는 `exit`. 녹화가 중간에 끊겼다면 같은 스크립트로 append하며, 이미 관찰한 것을 기록 생성만을 위해 다시 하지 않는다.

## 1. 첫 가설 — 명령 실행 이전

**먼저 바이너리를 실행하되, 출력에서 어떤 주소가 나올지 모른다고 가정하고 관찰 계획을 세운다.** `file`, `checksec`, `readelf -lW/-dW/-rW`, 정상 입력 1회 정도로 환경과 초기 출력을 확인한 뒤, 다음을 **해석 전 최초 추정**으로 기록한다.

1. 프로그램이 노출하는 값 각각의 출처(ELF/공유 라이브러리/부분 주소/숫자 등)를 어떻게 구분하고 어떤 주장을 **아직 확정할 수 없는지**.
2. 입력·저장 위치·길이 검사·복사의 독립 추적 계획.
3. 의도된 성공 조건을 섣불리 가정하지 않고 어떻게 분기/참조/레지스터를 좁힐지.
4. PIE/ASLR, NX, RELRO와 스택 정렬이 각각 어떤 부류의 분석/실패에 영향을 주는지.

**교사는 초기 분석·가설을 듣고 평가하며 무힌트 단계에서 페이로드 순서/가젯/offset은 제공하지 않는다.** 도움받는다면 그 시점부터 도움 범위를 명시하고 추가 변형 재평가가 필요하다.

## 2. 메인 — 새 바이너리 독립 실습

- 정적·동적 증거 최소 2종: `objdump/Ghidra`와 `GDB` 관찰의 차이, 현재 프로세스의 매핑 근거.
- 외부 의존 없는 로컬 성공 표식의 실제 실행. 복합 실패의 원인 분리: 구문/입력 제약, 주소 출처, PIE 기준, RIP 덮어쓰기 범위, 레지스터 인자, 스택 정렬, 제어 흐름 게이트.
- 시도 순서와 최초 실패를 그대로 기록. 최소 한 건의 **의도적으로 한 조건만 변경한 성공/실패 쌍**. 조건 변경 전 예측 필수.
- 성공률 실험: 최종 재현 스크립트로 **새 프로세스 20회** 호출. 모든 시도에 대해 `trial, pid(가능 시), result, exit_or_signal, failure_reason`을 `day161_trials.csv`에 기록. `n_success/20`으로 성공률, 세션 원시 로그와 재현 명령 명시. 특정 바이트/주소 조건 때문에 실패한 경우라도 분모에서 제외하지 않는다. 재시도가 있다면 별도 열에 구분해 숨기지 않는다.
- 결과에서 재현·보호기법 한계와 해석되지 않은 부분을 설명. 무조건 100%를 강요하지 않고 데이터와 원인 설명의 정직성을 평가한다.
