## 최초 무힌트 정적 분석 — 학생 답변
- 학생은 도움 없이 fgets, 개행 제거, strlen, 헤더 문자 범위 및 구분자, 본문 최대 길이, 초기화, category 저장, memcpy, 별도의 종료 문자 쓰기와 출력 흐름을 복원했다. 특히 최대 본문 복사 자체와 뒤따르는 null 종료 문자 쓰기를 구분하고, 최대 길이에서 인접 category가 변경되어 출력이 바뀔 가능성을 제시했다.
- 교사는 배포된 압축 ELF를 복원하여 SHA256 일치 및 objdump로 학생 분석을 대조했다. 핵심 원인 추론은 정확하다. 보완: 헤더를 포함한 문자열 길이는 2보다 커야 하므로 본문 허용 길이는 1~24이며, 원본 C 배열 선언 크기는 어셈블리 배치만으로 무조건 확정하지 않는다.
- 판정: 독립 정적 분석 통과. 학생의 실제 정상/경계/거부 입력 출력, 종료 상태, 메모리 관찰, 보호기법 확인 및 수정 설계는 아직 미제출. 교사 측 정적 검증을 학생 측 동적 실측으로 대체하지 않는다.

## 독립 동적 검증 — 학생 제출 원문
- 학생이 직접 실행한 터미널 출력과 pwndbg 관찰 및 checksec 결과를 채팅으로 제출. 아래는 제출 내용에서 프롬프트와 불필요한 공백을 정리한 발췌이며 교사의 재실행 결과가 아니다.

## 수정 설계 및 검증 과제
- 학생은 최초에 category 재배치와 최대 길이 23으로 제한을 제안. 재배치는 경계 오류를 해결하지 않고 길이 제한은 기존 기능을 축소한다는 피드백 후 배열 용량 25 제안. 검사 조건에서 등호 누락을 지적받고 <=로 교정. 수정 설계는 도움 후 통과, 23/24 허용 및 25 거부 예측은 학생 정답.
- 교사 작업 환경에서 원본 C 파일을 찾지 못해 SHA256 일치 ELF의 어셈블리와 문자열을 바탕으로 [복원 모델](day156_retest_model.c)을 작성했다. 원본 빌드 소스나 동일 바이너리로 주장하지 않는다. 교사 환경 GCC -O0에서 본문 길이 1/23/24/25 및 빈 본문/잘못된 헤더 총 6개 사례의 stdout과 종료 코드가 기존 ELF와 일치함을 검증했다.
- 학생은 모델을 별도 파일에 복사하여 방어적 수정 후 컴파일하고 기존 ELF 및 수정 모델의 23/24/25 길이 출력과 종료값을 비교한다. 이 결과는 복원 모델 수정 검증이지 기존 ELF 패치가 아니다. 학생 수정 실행 결과 미제출.

## 학생 수정 코드 검토 — 2026-11-20
- 학생 제출 코드: struct record의 label[24]를 label[25]로 확장하고, 길이 검사를 len > 25로 변경했으며, memcpy 전에 if (sizeof(rec.label) <= len) { puts("overflow"); return 4; }를 추가했다. 종료 문자 기록은 유지했다.
- 코드 검토: 실제 배열 용량 25이므로 len 24 이하만 복사 경로로 들어간다. 종료 문자 쓰기는 배열 내부에 위치한다. 25는 사전 거부되어 관찰했던 경계 오류가 제거된다. 원래 프로토콜의 최대 본문 24를 명시하는 len > 24를 유지하는 것이 더 적절하며, 현재 코드에서는 길이 25의 오류 메시지/반환값이 원본 모델과 달라진다. 기능상 허용 범위는 유지됨.
- 학생은 컴파일 및 실행 후 24까지 정상 출력, 25에서 경고 후 종료라고 보고하였다. 개별 23/24/25 원문 출력 및 종료 코드, 환경과 실제 fixed.c Git 제출은 아직 확인되지 않았다. 원본 ELF 수정이 아니라 별도 복원 모델 수정임을 유지한다.

## Day155 D+2 — 관측과 PIE 판정 구분
- 가상 100회 관측 조건(main/helper 런타임 절대주소 각 1종, stack 98종, libc 100종, main-helper 1종)에서 학생은 최초 PIE OFF/ASLR ON을 타당하게 추정하고 주소 충돌 가능성을 설명했다. 이후 절대주소와 ELF 상대 오프셋을 혼동하여 PIE ON 확정으로 판단을 변경했다. 최초 문제 표에서 절대주소라는 점을 명시하지 않은 교사 설명의 모호함도 기록한다.
- 교정: 런타임 절대주소와 이미지 상대 오프셋은 다르며 함수 간 거리 불변은 PIE ON/OFF에 공통이다. 관측만으로 ELF의 PIE 속성을 확정하지 않고 ELF 헤더/동적 플래그와 실행 환경을 대조한다. 변경 조건 재검증 대기.
