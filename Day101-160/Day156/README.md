## 사용자 동적 분석 — 정상 및 경계 반례
- 학생은 어셈블리에서 복사 시작 위치와 별도 무결성 검사 슬롯의 간격이 32바이트임을 확인했다고 보고. 허용 입력의 최대 복사량이 48바이트라는 점을 교사 질문 후 도출했다.
- 정상 입력은 교사 제공 바이너리 입력 생성 예로 실행하고 정상 통과했다고 구두 확인. 학생이 직접 구성한 최대 허용 길이의 입력으로 GDB에서 검사 슬롯이 A로 변경된 것을 확인했다고 보고. 이어 실행 시 **record integrity error** 출력이 Ghidra에서 확인한 오류 경로와 일치한다고 직접 보고.
- checksec 사용자 보고: Full RELRO, Canary, NX, PIE 활성화.
- 증거 수준: 어셈블리 위치와 GDB 관찰은 사용자 설명, 오류 문자열은 직접 보고. GDB 전체 덤프/종료 코드와 checksec 원문은 미제출. 목적지의 정확한 C 선언 크기는 아직 확정하지 않음.
- 교사 도움: 헤더 조건 해석, 바이너리 입력 생성 예, 정적 분석의 의미 및 디버거 명령 안내. 독립 분석과 도움을 구분한다. 학생은 쓰기 이후 검사라는 한계를 이해했으며, 다음 평가 단계는 오류 처리와 메모리 안전한 수정 방안, 경계 회귀 테스트 설명이다.


## 원인 및 수정 방안 구술 평가
- 학생은 최대 복사 범위가 컴파일러의 Canary까지 도달하지 않기 때문에 관측된 오류는 별도 무결성 검사에 의한 것이라고 설명했다. 교사 측에서도 배포 ELF의 해시와 디스어셈블리를 대조해 이를 확인하였다. 교사 확인은 사용자 독립 실측으로 기록하지 않는다.
- 학생은 복사 후 검사라는 한계를 설명하고, 복사 전에 목적지 배열 용량과 실제 복사량을 비교하는 수정안을 제시하였다. 수정 방향은 타당하다. 다만 근본 원인은 사후 검사 자체보다 **목적지 경계 검사의 누락**이며, 별도 무결성 검사를 제거하는 것은 수정의 필수 조건이 아니다.
- 교육상 다음은 정상 경계 및 초과 경계의 회귀 테스트 예상 결과를 설명하는 것. 소스 수준 수정의 실행 검증은 아직 수행하지 않았다.

## 수정안 검토 — 사전 목적지 경계 검사
- 학생이 원본 배열 선언 크기와 인접 슬롯까지의 거리를 구분해야 한다고 질문하여, 디컴파일 추정·정적 배치·동적 관찰의 증거 수준 차이를 설명함.
- 학생 독립 수정안: 복사 전에 `if (sizeof(목적지 배열) < uVar2 * 2)`가 참이면 종료. 실제 배열이 해당 스코프에 있고 기존 입력 검사를 유지한다면 타당. 포인터에 대한 sizeof는 배열 용량이 아니며, 복사량이 용량과 같으면 허용한다. 현 실습의 제한된 길이 범위에서는 곱셈 오버플로우 문제 없음.
- 수정 코드 실행 및 경계 회귀 테스트 실측은 아직 없음. 학생의 설계 답변과 실측을 구분함.

## CS 구술 평가 1/5 — 함수 프롤로그
- 최초 답변: 호출자 RBP 보존 및 스택 공간 확보는 정답, mov rbp,rsp의 목적은 회상하지 못함.
- 기준점에 관한 힌트 제공 후 학생은 함수 실행 중 RSP가 변할 수 있으므로 RBP를 현재 함수의 프레임 기준점으로 삼는다고 정확히 설명함. 초기 미답변과 힌트 후 교정을 구분. 후속 문항에서 프레임 기준점과 복원 원리를 재검증한다.

## CS 구술 평가 2~5/5 — 에필로그, ABI, 정렬, 레지스터 보존
- 2번: leave의 RSP=RBP 및 saved RBP 복원과 RSP+8, ret의 RIP=[RSP]를 학생이 정확히 설명. ret 이후 RSP+8은 교사가 보완.
- 3번: 정수 인자 레지스터 RDI, RSI, RDX, RCX, R8, R9 순서는 독립 정답. 스택 인자 위치 부호 초기 오답, 그림 힌트 후 return=[rbp+8], g=[rbp+0x10], h=[rbp+0x18] 정답.
- 4번: 진입 RSP%16=8, push rbp; sub rsp,0x38; push rbx 조건에서 sub 직후 8, call 직전 0, ABI 충족 모두 독립 정답.
- 5번: 학생은 RBX 복원 누락이 호출자 동작에 영향을 줄 수 있음을 이해했으나, leave; ret가 잘못된 복귀 주소를 읽을 수 있다고 판단한 부분은 주어진 프레임 조건에서는 오답. leave는 먼저 RSP를 RBP로 재설정하므로 RBX 저장 슬롯을 건너뛴다. RBX는 callee-saved이며 변경되었다면 반환 전 원래 값을 복원해야 한다. RBP 및 저장된 복귀 주소가 정상이라면 반환 자체는 가능하다. 교정 후 새 조건으로 확인 필요.

## CS 구술 재검증
- RBX 보존 규약 오류를 설명한 후 새 조건(호출자 RBX=100, 피호출 함수가 200으로 변경하고 복원 없이 leave; ret)을 제시. 학생은 복귀 가능, RBX=200, 레지스터 보존 규약 위반이라고 정확히 답했다. 주어진 정상 프레임 조건에서의 교정 확인 통과.
- CS 5문항 응답 완료. 최초 답변에서 프레임 기준점 회상 부족, 스택 인자 위치 부호 혼동, leave에 대한 오개념이 나타났으므로 무힌트 전 문항 통과로 평가하지 않는다. 별도 누적 및 D+2 복습과 최종 기록은 남아 있음.

## Day154 D+2 — 보호기법의 범위와 한계
- 학생은 모든 보호기법이 켜진 상태에서 인접 지역변수 변경이 가능한 이유를 독립 설명했다. Canary 값이 변경되지 않으면 해당 비교 검사를 통과할 수 있음, NX는 실행 권한을 제한하고 쓰기 자체는 막지 않음, PIE는 입력 경계 검사가 아님, Full RELRO는 동적 재배치를 마친 GOT의 쓰기 방지를 위한 것이며 스택 데이터의 쓰기를 막지 않음. 핵심 판단 정답.
- 정밀화: Canary 위치는 빌드별로 달라질 수 있고 PIE는 위치 독립 실행 이미지를 통해 ASLR 적용 시 로딩 주소 무작위화를 가능하게 한다. 학생의 PIE 설명에는 구체적 역할이 생략되었으나 질문의 핵심인 쓰기 범위 검사의 부재는 이해함. Full RELRO 설명은 일반적인 Linux ELF 동적 링크 환경 기준으로 타당.
- D+2 통과. Day040~050 누적 복습은 기존 정렬 문제 반복 대신 프레임 포인터 없는 함수의 스택 인자 위치와 호출 직전 정렬을 함께 판단하는 새 조건으로 진행한다.

## 누적 복습 — 프레임 포인터 생략 조건
- 함수 진입 RSP%16=8, 프레임 포인터 없이 sub rsp,0x28 후 call printf 조건. 학생 최초 답: 7/8번째 인자 +0x38/+0x40, 복귀 주소 +0x8, 정렬 만족. 정렬은 정답, 슬롯 위치는 오답.
- 교정: 진입 시 복귀 주소 [rsp], 7/8번째 인자 [rsp+8]/[rsp+0x10]. 0x28만큼 RSP 감소 후 각각 +0x28/+0x30/+0x38. 기존 데이터는 이동하지 않음. 새 조건 독립 재검증 대기.
