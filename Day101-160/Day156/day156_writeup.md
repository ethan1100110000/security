# Day156 — W06 종합평가 기록 (2026-11-19)
## 판정
학습·구술·교정 후 복습을 수행. **독립 블라인드 평가 통과는 보류**한다. 최종 계획의 Day156/W06 및 R05/R07/R21을 기준으로 최초 도움받은 부분과 재검증을 구별한다.

## 대상 및 근거
- 교사가 제작하여 제공한 로컬 Linux x86-64 stripped PIE ELF. SHA256: `616ff0a7e73176034294a9c3997c4d070a005a11d515417fbf59050e02a5f848`. [배포 데이터](day156_target.elf.xz.b64), [복원 및 해시 확인 스크립트](unpack.sh), [실습 상세 기록](README.md).
- 교사 환경에서 첨부 파일 해시, ELF 유형, GNU_STACK RW, GNU_RELRO 및 BIND_NOW/PIE 플래그를 확인. 학생의 checksec 보고는 Full RELRO, Canary/NX/PIE ON. 교사 확인을 학생 원문으로 대체하지 않는다.
- 학생은 Ghidra와 objdump를 이용해 입력 레코드 구조, 길이 조건 및 복사 흐름을 파악하고, GDB에서 정상/경계 반례의 결과를 대조했다.

## 분석 및 수정안
- 사용자가 제어하는 복사 길이에 대해 원본 입력 길이 검사는 있지만 목적지 객체 용량 검사가 빠졌다고 학생이 판단.
- 학생이 보고한 정적 배치와 GDB 관찰은 복사 이후 인접 무결성 검사 변수 변경을 뒷받침한다. 정상 레코드는 통과, 최대 허용 크기의 레코드에서 `record integrity error`가 출력됐다고 보고. 이는 사후 검사 오류 경로와 일치한다. 전체 GDB 덤프와 종료 코드 미제출.
- 정확한 원래 배열 선언 크기는 stripped ELF의 변수명이나 슬롯 간격만으로 확정하지 않는다. 복사 범위와 인접 변수 오염의 관찰 사실을 구분.
- 학생이 사전 목적지 용량 검사를 제안. 실제 배열이 있는 경우 복사 전에 `sizeof(buffer)`와 복사량을 비교하고, 포인터인 경우 실제 용량을 별도로 사용. 가정 용량 32B에서 30/32B 허용, 34B 거부를 정확히 예측. 패치 실행 및 회귀 테스트 실측은 미수행.

## CS 및 복습
| 항목 | 최초 답변 | 이후 확인 |
|---|---|---|
| 프롤로그 | 기준점 의미 미회상 | 힌트 후 RBP 기준점 설명 |
| 에필로그 | 핵심 정답 | ret의 RSP 증가 보완 |
| 정수 인자 ABI | 레지스터 정답, 스택 위치 부호 오류 | 교정 후 위치 정답 |
| 16B 정렬 | 정답 | 독립 통과 |
| callee-saved | 복귀 주소에 관한 오류 | RBX 보존 위반과 정상 반환 구분 재검증 |
- Day154 D+2: Canary/NX/PIE/RELRO 모두 활성화 상태에서도 경계 초과 데이터 쓰기가 가능함을 독립적으로 설명. Canary의 슬롯 위치는 빌드 의존이라는 점 보완.
- 누적 복습: 프레임 포인터가 없는 함수에서 RSP 상대 오프셋 초기 오답. 변경 조건 RSP=0x1008, sub rsp,0x38에 대해 RSP=0x1008-0x38(0xfd0), 복귀 주소 +0x38, 7/8번째 인자 +0x40/+0x48 독립 정답. 앞선 교정과 구분하여 기록.

## 한계 및 다음 조치
- 최초 블라인드에서 헤더 조건 해석, 바이너리 입력 생성 예, GDB 조작, 근본 원인 정밀화의 도움을 받았다. 독립 발표 10분을 실제로 수행했다고 기록하지 않는다.
- 사용자 측 정적·동적 증거는 주로 채팅의 직접 설명과 오류 문자열이며, 재현 입력 원본 및 전체 터미널/GDB 로그와 환경 정보가 Git에 아직 확인되지 않았다. 정확한 원본 C 선언 및 빌드 명령 미확정.
- 학습 내용 정리 및 재검증은 수행했으나, **Day156/W06 독립 평가 보류**. 새 미지 문제에서 독립 분석 및 실제 원자료와 재현 기록을 확보해 평가해야 한다. 이미 해설한 동일 문제를 다시 독립 시험으로 계산하지 않는다.
