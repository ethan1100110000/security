## 1. 메인: 범위 검사와 객체 수명

src는 살아 있는 8바이트 배열, malloc은 성공한 것으로 가정했다.

```c
char *dst = malloc(16);
size_t capacity = 16;

free(dst);

if (length <= capacity && length <= src_size)
    memcpy(dst, src, length);
```

length=8, src_size=8이면 수치상의 두 범위 조건은 통과한다. 그러나 free(dst)에서 할당 객체의 수명이 끝난 뒤 memcpy가 그 영역에 쓰므로 use-after-free다. 과거 용량값이 16으로 남아 있어도 객체 수명이 복원되지 않는다.

사용자는 free 이후 dst에 접근하는 것이 잘못이라고 설명했다. free를 if문 다음으로 옮기면 복사와 복사 생략 두 경로 모두에서 해제된다고 답했다.

### 정리 순서
1. 할당 성공 확인.
2. 원본 실제 길이와 목적지 용량 검사.
3. 허용된 경우 복사.
4. 복사 결과를 사용하는 작업이 있으면 그 사용까지 완료.
5. 두 분기가 합쳐지는 정리 지점에서 해제.

이번 예제의 if는 조기 return이 없는 형태다. 거부 경로가 return으로 먼저 나가는 코드라면 해제 지점에 도달하도록 별도 정리가 필요하다. 오늘은 이런 조기 반환 코드나 할당 실패를 실행한 것은 아니다.

## 2. 메인: 접근 권한은 별도 조건

dst가 살아 있는 16바이트 읽기 전용 메모리 영역이고 원본도 충분할 때, 8바이트 복사는 범위와 수명 조건을 만족해도 목적지 쓰기가 허용되지 않는다.

사용자는 처음 권한 사례에서 막혔으나, memcpy는 src 읽기와 dst 쓰기라는 힌트 후 “read-only 공간에 write하려고 하므로 문제”라고 설명했다.

### 타입 변환과 실제 보호 권한
(char *)dst 형변환은 포인터 표현식의 타입을 바꿀 뿐 실제 메모리 보호 권한을 변경하지 않는다. 사용자는 이 질문에는 모르겠다고 답했으며 교사 설명을 받았다. 이를 독립적으로 증명한 것으로 기록하지 않는다.

읽기 전용 원본의 수정 가능한 복사본을 만들려면 별도의 쓰기 가능한 메모리를 준비한다. 사용자는 write 권한이 있는 메모리라고 답했다. 교사는 목적지 용량과 수명 조건도 함께 필요함을 연결했다.

### 코드 위치와 안전 조건
| 조건 | 관련 위치 | 오늘 확인한 의미 |
|---|---|---|
| 범위 | length와 src_size/capacity 비교, memcpy 길이 인자 | 원본 읽기와 목적지 쓰기가 유효한 범위인지 |
| 접근 권한 | dst가 가리키는 영역의 생성·보호 설정, memcpy의 쓰기 | 범위 안이어도 쓰기가 허용되어야 함 |
| 객체 수명 | 할당·free·최종 사용의 순서 | 수명이 끝난 객체를 길이 검사만으로 사용할 수 없음 |

세 조건을 구분한 대화 결과이며, 실제 보호 설정이나 실행 결과를 새로 만들지 않았다.

## 3. CS: 작은 unsigned 타입으로의 크기 변환

```c
size_t length = 260;
uint8_t small_length = (uint8_t)length;
```

uint8_t가 존재하는 환경에서 표현 범위는 0~255다. 변환 결과는 256으로 나눈 나머지인 4다. 사용자는 처음부터 4라고 예상했다. 변환은 원래 length 변수 자체를 변경하지 않는다.

### 검사값과 실제 사용값의 불일치
원본은 260바이트로 충분하고, 목적지는 살아 있는 쓰기 가능한 16바이트 배열로 가정했다.

```c
uint8_t small_length = (uint8_t)length;  // length = 260

if (small_length <= 16)
    memcpy(dst, src, length);
```

검사는 4 <= 16을 보므로 통과하지만, memcpy는 변환 전 length=260을 사용해 목적지 범위를 벗어나는 복사를 시도한다. 그 이후 실제 종료 증상이나 crash 여부는 실행 없이 확정하지 않는다.

사용자는 검사 통과를 예상했고, memcpy 인자를 다시 확인한 뒤 실제 복사 길이는 260이라고 답했다. 목적지 용량과 비교할 값으로 변환 전 length를 선택했다.

### 값 보존과 용량 검사는 별개
- 실제 복사에 쓰는 원래 length를 src_size와 capacity에 비교한다.
- 파일 형식 등으로 uint8_t 저장이 필요하면 변환 전에 값이 표현 범위 안인지 확인한다.
- length가 size_t이므로 음수는 없고, length > UINT8_MAX를 거부하면 uint8_t 변환에서 값이 보존된다.
- uint8_t에 표현 가능하다는 것만으로 16바이트 목적지에 들어간다는 뜻은 아니다.

사용자는 변환 전에 0~255인지 검사해야 한다고 답했다. 교사가 unsigned 원본에는 상한 검사를 적용하는 코드 형태를 설명했다. 새 변환 프로그램이나 출력은 없다.

## 4. 보안 2회독: call/ret과 스택 프레임

설명 범위는 일반적인 x86-64의 near call/ret과 아래 프레임 포인터 구성이다. 모든 함수가 rbp 프레임을 만들거나 동일한 오프셋을 사용하는 것은 아니다.

```asm
push rbp
mov  rbp, rsp
```

- call은 call 바로 다음 명령어의 복귀 주소를 스택에 저장한다.
- push rbp는 호출자의 이전 rbp 값을 저장한다.
- mov rbp, rsp는 현재 함수의 프레임 기준을 설정한다.

사용자는 push rbp가 복귀 주소를 저장한다고 답했다. call과 push rbp가 각각 저장하는 값의 차이를 교정했다.

### 주소 예제 1: 프레임 진입
call 직후 rsp=0x1000이고 그 위치에 복귀 주소가 있다고 가정했다. push rbp 후 rsp=0x0ff8이 되고 이전 rbp를 저장한다. mov rbp, rsp 후 rbp=0x0ff8이다.

| 주소 | 저장 내용 | 이 프레임의 위치 |
|---|---|---|
| 0x0ff8 | 호출자의 이전 rbp | [rbp] |
| 0x1000 | call이 저장한 복귀 주소 | [rbp+8] |

사용자는 처음 위치 추적에서 막혔고 표를 본 뒤 복귀 주소 위치를 [rbp+8]로 맞혔다. 이는 힌트 후 답변이다.

### 프레임 정리와 반환
```asm
mov rsp, rbp
pop rbp
ret
```

- mov rsp, rbp: 이번 프레임의 정리 시작 위치로 rsp를 되돌린다.
- pop rbp: 현재 [rsp] 값을 rbp로 복원하고 rsp를 8 증가시킨다.
- ret: 현재 [rsp]의 복귀 주소를 rip에 넣고 rsp를 8 증가시킨다.

ret은 rbp 기준으로 주소를 직접 찾는 것이 아니라 [rsp]를 읽는다. [rbp+8]이 복귀 주소라는 설명은 위 프레임 진입 형태에서의 위치 관계다.

사용자는 pop 추적에서 막혀 두 동작 설명을 받았다. 이어 “rip = [rsp]가 되므로 복귀 주소가 rip에 들어간다”고 설명했다.

### 주소 예제 2: 독립적인 조건 변경 추적
초기 조건:
- rsp=0x2000
- [0x2000]=0x3000: 저장된 이전 rbp
- [0x2008]=0x401050: 복귀 주소

| 시점 | rbp | rsp | 의미 |
|---|---|---|---|
| pop rbp 직후 | 0x3000 | 0x2008 | 이전 rbp 복원, 스택 위치 8 증가 |
| 이어 ret 직후 | 0x3000 | 0x2010 | rip=0x401050으로 복귀 |

사용자는 pop rbp 직후 rbp=[rsp]=0x3000, rsp=0x2008, 새 [rsp]=0x401050을 교사 추가 힌트 없이 맞혔다. ret 직후 값은 교사가 덧붙였다. 실제 GDB 레지스터 관찰이 아니라 손 추적 결과다.

## 5. 오늘 확인한 내용과 남은 약점

| 영역 | 확인한 내용 | 확인 수준 |
|---|---|---|
| 메인 수명 | free 뒤 접근 금지, 사용 후 해제 위치 | 직접 설명 |
| 메인 권한 | read-only 목적지에는 쓰기 불가 | 힌트 후 설명 |
| 형변환·권한 | 캐스트는 실제 보호 권한을 바꾸지 않음 | 교사 설명, 재확인 필요 |
| CS | 260→4, 검사값과 실제 복사 길이 차이 | 예측 및 코드 해석 |
| CS 변환 조건 | 변환 전 0~255 범위 확인 | 직접 답변 |
| 복습 | saved rbp와 복귀 주소 구분 | 교정과 표 설명 후 확인 |
| 복습 | pop의 값 복원과 rsp 증가 | 새 주소 조건에서 독립 추적 |

권한과 call/ret은 반복 설명만으로 숙달 처리하지 않는다. 다음 학습에서 작은 실제 관찰과 연결해 확인할 항목이다.
