# Day115 - Toy Parser Harness

Day114의 `parse_record()`를 `day115_parser.c`와 헤더로 분리하고 `static`을 제거했다. `nm -g`에서 `T parse_record`를 확인해 다른 object 파일에서 호출 가능한 전역 함수임을 검증했다.

stdin harness는 `read(STDIN_FILENO, ...)`의 입력 주소와 반환 길이를 parser에 전달한다. file harness는 `argv[1]`의 파일을 열어 같은 방식으로 전달하며, AFL++에서는 `@@`가 현재 변이 입력 파일의 경로로 교체된다.

두 harness 모두 정상 입력에서 동일한 결과를 출력했다. 20바이트 Payload를 포함한 crash 입력도 ASan에서 `WRITE of size 20`과 16바이트 `payload`의 `stack-buffer-overflow`를 발생시켜 crash가 숨겨지지 않음을 확인했다.

`afl-showmap -e`에서는 두 harness가 각각 6개 tuple을 기록했지만, 서로 다른 바이너리의 map이므로 이를 합쳐 12개 edge로 해석할 수 없다. 전용 harness는 불필요한 초기화와 외부 상태를 제거해 parser 도달률·실행 속도·coverage 집중도를 높이되, 실제 caller의 필수 전제조건은 보존해야 한다.
