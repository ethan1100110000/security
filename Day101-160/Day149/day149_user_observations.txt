Day149 / 2026-11-10 / W05 3/5 — 사용자 직접 제출 실행·문답 발췌
대상: Day147/archive_desk (로컬 WSL, GDB/pwndbg). 원본 전체 로그 및 입력 파일 자체는 Git에 올리지 않았음.

[실습 전 예측과 교정]
함수 Submit: C 소스 record[48] (원본 Day147 challenge.c 확인).
어셈블 스택 record 시작 rbp-0x40, Canary rbp-0x8. 시작~Canary=0x38=56B.
사용자는 48바이트가 Canary 직전, 56바이트가 Canary까지 도달한다고 처음 생각함.
교사 설명: buf48B + padding8B + Canary8B 구분.
실행 파일 입력: b"2\n" + b"A"*N, N=48,56,57 (교사 생성법 제시).

[사용자 직접 실행 보고]
N=48: "received: 48" / 정상 종료.
N=56: "received: 56" / 정상 종료.
N=57: "stack smashing detected" (정확한 read 반환길이 메시지는 제출되지 않았음).
=> 56도 선언된 record[48] 밖으로 쓰며, Canary가 보존되면 검사가 통과할 수 있음.
=> 57은 Canary 첫 바이트에 도달할 것으로 예측, 다음 GDB로 직접 확인.

[GDB — 사용자가 제출한 원본 그대로]
pwndbg> x/8bx $rbp-0x8
0x7fffffffdf58: 0x41    0x94    0xdf    0x1b    0xbf    0xad    0xff    0x9b
pwndbg> x/8bx $fs_base+0x28
0x7ffff7fb1768: 0x00    0x94    0xdf    0x1b    0xbf    0xad    0xff    0x9b
사용자 해석: "'A'로 덮었으니까 0x00이던 게 0x41로 덮였음".
=> 낮은 주소의 첫 바이트만 변경, 나머지 7B는 동일. 다른 세션에서 Canary 실제 8B 값은 달라질 수 있음.

[조건 변경/CS — 예측 및 실측]
입력 파일: b"2\n" + b"A"*56 + b"\x00".
사용자 예상: 길이 57이지만 원래 Canary의 첫 바이트 0x00과 같은 값으로 덮으면 검사에서 걸리지 않음. 메모리 취약점이 사라진 것은 아님.
사용자 실측: "ㅇㅇ 예상대로다" → 교사 요청의 received:57/정상 종료 확인 응답.
=> 메모리 경계 위반과 Canary 검출 여부는 별개. 이 결과는 Canary 검사 우회 조건의 한 사례, 완전한 실행흐름 변경/Exploit 성공 증거 아님.

[보안 복습 Day081 — Git 근거 대조 후 문답]
Day081 write_up.txt: glibc 2.35 __free_hook 심볼 주소 및 writable 확인, write 성공하나 free() 호출 경로에서 후킹 실행 안 함.
사용자 회상: "호환성 때문에 버전이 바뀌었어도 남겨놓은 걸로 기억... 존재하고 writable하지만 의미가 없어서 공격에 활용못했었나" → 과거 기록과 대조해 맞음.
실행 target 판단: writable + 주소 파악 + 실제 호출 경로 + 함수 인자와 호출 규약 호환.
설명용 action(data), system("/bin/sh")에 대해 사용자는 타입을 맞춰 전달하면 된다고 답함.
교사가 초기 예시의 함수 포인터 타입 void (*)(char*) = puts 부정확함을 설명; 실제 함수 반환형과 const char* 인자에 맞춰 int (*)(const char*) 권고.
최종 반례: void (*action)(int)를 system 주소로 덮는다고 system("/bin/sh") 실행 보장되지 않음; 사용자 '정수 타입으로 받으면 제대로 실행이 안 될 듯'이라 답.
=> ABI/포인터 인자 불일치와 C 함수 포인터 타입 호환성이 중요. 실제 함수포인터 타입 변환 강제실행 관찰 아님.

[도움·범위]
입력파일 작성/브레이크포인트 명령/메모리 배치 교정/반례 제시는 교사가 제공. 실측 GDB 바이트와 최종 결론, 조건 변경 예상은 사용자.
Day149 기록은 세션에서 진행한 위 과제에 대한 기록. GitHub의 최신 XLSX 일일 행은 API의 바이너리 UTF-8 반환 오류로 이번 세션에서 직접 확인되지 못했음(마지막 계획표 상세 문구 확정이라고 주장하지 않음).
새로 만든 과제 바이너리·해시·전체 원시 실험 로그/툴 버전/시간 미제출. Day081 힙 실험 재실행 안 함.
