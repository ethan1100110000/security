## Day98 — indirect call / function pointer 분석

검증 함수는 `param_1 - 0x14`가 3 이하인지 unsigned 비교하여 `param_1`을 `20~23`으로 제한한다. 이후 계산한 인덱스로 함수 포인터 테이블의 함수를 선택한다.

```c
index = param_1 - 20;
table[index](param_2, output, 12);
```

함수 포인터 테이블은 다음과 같다.

```text
20 → 0x1300
21 → 0x13d0
22 → 0x14b0
23 → 0x15a0
```

어셈블리에서는 다음 간접 호출로 구현돼 있었다.

```asm
call qword ptr [rcx + rax*8]
```

`RCX`는 테이블 시작 주소, `RAX`는 인덱스이며 함수 주소가 8바이트이므로 인덱스에 8을 곱한다. 호출 인자는 `RDI=입력`, `RSI=출력 버퍼`, `RDX=12`로 전달된다.

`0x1300`과 `0x13d0` 경로를 역산한 결과 비출력 바이트와 NUL이 포함돼 제외했다. `0x14b0` 함수의 `ROL8`, XOR, 상태 갱신을 역순으로 계산하여 입력 `CALL_PTR_98!`을 복원했다.

최종 입력은 다음과 같다.

```text
22 CALL_PTR_98!
```

GDB에서 인덱스가 `2`이고 `[RCX+RAX*8]`에 `PIE base+0x14b0`이 저장된 것을 확인했다. `si` 실행 후 실제 `0x14b0` 함수로 진입하는 것도 검증했다. 마지막 문자와 함수 선택값을 각각 변경한 두 실패 입력도 모두 거부됐다.
