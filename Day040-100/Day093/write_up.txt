## Day93 Write-up — Loop Verifier

### 목표

Ghidra로 반복문 기반 검증 로직을 분석하고, 비교 대상에서 입력값을 역산한다.

### 분석한 검증식

```c
key_index = (3 * i + 1) % 10;
x = input[i] ^ data[key_index];
cVar1 = ROL8(x, (i % 3) + 1);
output[i] = cVar1 + 7 * i + 3;
```

생성된 `output` 10바이트는 `memcmp`로 `DAT_00102060`과 비교된다.

### 역산 순서

정방향의 마지막 연산부터 반대로 취소했다.

```c
cVar1 = (target[i] - (7 * i + 3)) & 0xff;
x = ROR8(cVar1, (i % 3) + 1);
input[i] = x ^ data[(3 * i + 1) % 10];
```

1. `target[i]`에서 `7*i+3`을 뺀다.
2. `ROL8`의 역연산인 `ROR8`을 적용한다.
3. 같은 key 바이트로 다시 XOR해 입력을 복원한다.

### 결과

```text
key: R3-L00P-7N
ACCESS GRANTED
```

### CS 정리

* `strcmp`는 `\0`을 만날 때까지 비교한다.
* `memcmp`는 `\0`과 관계없이 지정된 길이만큼 비교한다.
* 비교 길이가 실제 버퍼보다 크거나 문자열에 널 종료가 없으면 범위 밖 읽기와 UB가 발생할 수 있다.
* 비교 길이가 너무 짧으면 입력의 앞부분만 일치해도 인증을 통과하는 부분 비교 문제가 생길 수 있다.

### 느낀 점

이전 문제와 마찬가지로 정방향 연산을 역순으로 취소하는 문제였다. 다만 key 인덱스 계산, XOR, 비트 회전, 1바이트 덧셈이 결합되어 흐름을 분리해서 이해하는 것이 중요했다.
