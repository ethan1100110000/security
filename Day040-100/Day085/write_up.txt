## 프로그램 동작 흐름
1 - 9 번까지 메뉴 루프 형식
1 add small - 작은 chunk malloc
2 delete small - free
3 show small - 출력
4 edit small - write
5 add large - 큰 chunk malloc
6 delete large - free
7 show large - 출력 
8 trigger - callback함수 호출 rbp = control_region(전역변수 bss) + 0x4000  call rbp + 0x50
9 exit

## 계획
small large free에서 둘 다 null로 초기화 없음 uaf 가능
edit로 small chunk 전체 write 가능

1. add small - free - show 소스를 봤을 때 add small하면 chunk 마지막 16바이트에 chunk의 주소 , callback함수 주소 가 들어가는 것을 확인 즉 free이후 show 하면 방금 할당한 chunk (a)의 주소 pie함수 주소를 알 수 있다
pie, heap leak
tcache에 들어간 chunk의 첫 8바이트는 tcache에 chunk가 한개일 경우 a >> 12 값이므로
이건 target을 encode할 mask로 사용
leak된 pie 함수는 gdb vmmap에서 pie base를 확인 leak한 함수의 offset을 구한다 이제 leak - offset으로 
pie_base 구함

2. 다시 add small 로 a chunk 회수 이후 한번 더 small add tcache count를 2로 만들기 위한 chunk(b)
b - a 순서로 free tcache 상태는 a -> b -> 0 a의 주소를 알고있으니 edit로 a의 next를 encode_target으로 
바꿔야 함
tirgger가 rbp에 전역변수인 control_region + 0x4000 을 넣기 때문에 여기를 fake stack 즉 target으로 사용
gdb에서 p/x control_region + 0x4000 명령으로 이 공간의 offset을 찾는다 pie가 켜져있기 때문에 아까 구한
pie_base를 더해 target의 주소를 잡고 target ^ a >> 12 연산으로 encode_target
a의 next를 encode_target으로 덮는다 이제 tcache 구조는 a -> target
두 번의 malloc으로 target을 반환 edit로 fake stack 내용을 적어야 한다

3. fake stack 작성에 필요한 조각은
ret, pop_rdi, leave_ret, system
system을 구하려면 libc base를 알아야 하는데 여기서 add large가 필요 하지만 문제가 생김
large chunk를 free할 때 top chunk에 흡수되는것을 막느 guard chunk가 필요한데 chunk사이즈를 내가 정할 수 없어 앞에 tcache 흐름이 꼬일 수 있음 순서를 바꿔서 libc leak를 가장 위로 올려서 해결했다
add small로 guard를 만들어주고 free unsortedbin에 들어간 chunk를 확인 
show 로 fd값을 leak하고 gdb에서 libc base를 확인 leak offset을 구한다 libc_base 도출
system 주소 구함

4. bss 작성
rbp에 넣을 8바이트 더미 + ret + pop_rdi + system + "/bin/sh" 문자열(binsh 주소를 구해도 괜찮지만 그냥
이렇게 넣음) + padding + leave ret
