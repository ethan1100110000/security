# 2027 보안 대학원 PwnLab 중심 엄격 학습계획 (2026-10-27 개정)

- **주력:** 경희대 PwnLab의 취약점 분석·리버스 엔지니어링·익스플로잇. 한양대 SSLab·서강대 IS Lab·성균관대 SecAI 병행. AFL++·AIMFuzz·BASTAG는 생략하지 않는다.
- **진도:** 실제 마지막 완료 Day와 다음 과제는 [progress_log.md](progress_log.md)의 Current Pointer만 따른다. 30주 계획 및 Day142~276의 135개 일일 과제는 [엑셀](hanyang-research-plan-2027.xlsx)에 있다. 엑셀 날짜는 예정일이며 실제 수행일과 구분한다.
- **엄격 규칙:** 매일 메인·CS·보안 복습·Write-up/실험 증거를 모두 수행한다. 메인/CS/복습/기록 네 영역 모두 완료하고 Git 근거 경로를 기록해야 하루 완료. 어려워도 문제·실험·논문·복습 **생략/축소/대충 넘어가기 금지**. 미완료 과제는 다음 학습일 **같은 Day**에서 이어가며 다음 단계 진입 불가.
- **도움받은 경우:** AI/해설/힌트 이용 사실을 기록한 뒤 마지막에 조건 변경 또는 유사 문제를 무힌트로 재검증해야 완료.
- **시간:** 메인 120분·CS 30분·복습 30분은 분배 참고값이다. 2026-10-27 사용자 확인에 따라 시간 측정·최소 시간 충족을 완료 조건으로 삼지 않는다. 과제·실험 근거·이해와 조건 변경 재검증·기록을 기준으로 판정하고, 시간을 채우기 위한 추가 문제나 같은 종합 설명의 반복을 요구하지 않는다. 이해 미달은 같은 Day로 이월한다.
- **계획 날짜:** 학습 지연은 숨기지 않고 실제 완료일을 별도 기록한다. W30 예정 종료는 2027-05-04이며 늦어져도 과제를 삭제하지 않는다. 대학원 원서/학점인정 신청 같은 외부 마감은 별도로 점검한다.
- **실습 윤리:** 본인 코드 또는 허가된 CTF/로컬 바이너리만 분석한다.
- **진도 원장:** [progress_log.md](progress_log.md)의 Current Pointer. 엑셀과 Markdown 계획을 변경했다고 진도가 완료된 것은 아니다.

## 진행 기준

1. 시작 시 progress_log.md, 본 계획, review_rules.md와 엑셀의 해당 Day를 확인한다.
2. 사용자 예상 → 실제 관찰 → 오류 교정 → 새로운 조건에서 재검증 → 짧은 write-up 순으로 진행한다.
3. 도움받은 부분은 기록한다. 종합 설명에서 드러난 오답을 조건 변경 문제로 재검증했다면 같은 발표를 처음부터 반복시키지 않는다.
4. 자료에는 환경·명령·입력·관찰값·가설·반례·수정·한계와 실제 Git 경로를 남긴다.
5. 커밋·로그 갱신까지 마치면 검증한 Day를 완료 처리한다. 계획 수정만으로 진도를 전진시키지 않는다.
6. 운영 기준의 최신 변경은 본 문서가 기준이며, 과거 Day write-up의 시간·계획 문구는 당시 기록이다.
